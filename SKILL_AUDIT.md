## 4. Were any frontend design skills used?

**No.** None of `design-taste-frontend`, `frontend-design`, `high-end-visual-design`,
`minimalist-ui`, `industrial-brutalist-ui`, `gpt-taste`, or `stitch-design-taste` were used.

The UI was built with:
- **shadcn/ui** components that shipped with the original starter template
  (`components/ui/*`: button, input, card, label, etc.), and
- **hand-written** components added during the build (badge, textarea, select, table, and
  all feature components under `components/leads/*` and `components/contractors/*`),
- styled with **Tailwind CSS v4** and the starter's existing CSS-variable theme.

No design system, style board, image generation, or aesthetic-direction skill produced
any of it.

## 5. Did any skills create design standards, component patterns, or UI conventions?

**No skill created them.** The project *does* have consistent conventions, but they were
established manually during development, not by a skill. For transparency, the conventions
that emerged are:

- **Component library:** shadcn/ui ("new-york" style, `zinc` base color) from the starter;
  no `DESIGN.md` or skill-authored design spec exists.
- **Layout pattern:** server components fetch data; small `'use client'` components handle
  interactivity; forms use React 19 `useActionState` with server actions.
- **UI primitives:** `Card`/`Table`/`Badge`/`Select`/`Input`/`Textarea`/`Button` reused
  across pages; status shown via `Badge` variants; lists via the shared `Table`.
- **Conventions file:** none generated by a skill. The closest things to "standards" are
  `lib/leads/constants.ts` (status/label/variant maps) and `lib/nav.ts` (role-based nav),
  both hand-written.

These are ordinary engineering conventions, not skill outputs.
